# 条款重排校稿台

本地运行的条款校稿工具：粘贴一份带编号的条款文本，在页面上**编辑正文、调整顺序、删除条款、合并条款**，
随时预览连续重排后的新编号与引用；修复所有失效引用后，才能下载与预览完全一致的纯文本。

- 后端：Python + FastAPI（无状态接口，草稿只存在浏览器内存）
- 前端：原生 HTML / CSS / JavaScript，无框架、无构建步骤
- 刷新或关闭页面即丢弃草稿，服务端不保存任何数据

## 启动（一条命令）

```bash
docker compose up --build
```

启动后在浏览器访问：

> **http://localhost:8000**

停止：在终端按 `Ctrl+C`（如需后台运行用 `docker compose up --build -d`，停止用 `docker compose down`）。
网络等待、请求失败期间页面会怎样（哪些操作会临时锁定、失败后如何恢复）见下文
「网络等待与失败时会怎样」一节；等待时通常只需静候状态条消失，失败时按提示重试即可，草稿不会丢失或回退。

## 输入格式

导入区每行一条，共 **2～40 行**：

```
编号|正文
```

- 编号必须是正整数，从 **1 开始连续排列**，不可重复、不可缺号。
- 正文内用 `[[编号]]` **显式引用**其他条款，例如 `按 [[1]] 验收`；
  引用编号两侧不可有空格（`[[ 1 ]]` 视为格式错误）。
- 每条条款只占**一行**（正文内部不能换行）；竖线只在第一个处分隔，正文里可以再含 `|`。
- 允许引用自身。

以下任意问题都会导致**整份拒收**，并逐行列出原因：格式错误、编号重复/不连续、
引用无目标（编号超出范围）、空行或空正文、未闭合的 `[[`。

## 使用规则（引用如何绑定）

- 导入时，正文里的 `[[编号]]` 立即绑定到该编号对应的**那条原始条款**（内部使用稳定标识，
  显示编号会随重排实时更新）。
- 编辑某条正文时，新输入的 `[[数字]]` 按**点击保存那一刻**页面上显示的编号绑定。
  因此之后无论怎样拖拽重排，引用都不会转指“占用了旧号码”的另一条条款。
- 保存时同样校验：正文不能为空、不能跨行、引用编号必须在当前范围内，否则拒绝保存并提示。
- 删除被其他条款引用的条款时，会提示影响范围；删除后，指向它的位置标为
  **`[[原N?]]`（红色失效标记）**，顶部横幅和条款卡片同时标出引用来源（第几条/原第几条）
  与失效位置。
- 存在失效引用期间，**「下载纯文本」按钮禁用**，导出接口也会拒绝（HTTP 409）。
  编辑对应条款，把失效标记改成有效的 `[[当前编号]]` 或删掉该标记并保存，即完成修复。
- **合并条款**：勾选两条不同条款后点工具栏「合并所选」。系统按**当前显示顺序**把两条正文用
  全角分号「；」连接（较前正文；较后正文）；合并结果占据较前条款的位置并**沿用它的身份**，
  较后条款移除，其余条款相对顺序不变。原来指向较后条款的所有引用——包括两条待合并正文里的
  引用——都改指合并结果；指向较前条款及其他条款的引用不变；合并前已失效的引用仍保持失效。
  合并后编号自动重排，之后继续编辑或拖拽重排，引用也不会转指。正在编辑正文时须先**保存或取消**
  才能合并；合并失败（如服务端校验不通过）不会改动草稿。
- 右侧预览与下载文件由服务端同一套解析逻辑生成，格式均为 `新编号|正文`，保证完全一致。

## 网络等待与失败时会怎样（迟到响应防护）

所有操作（导入、保存、合并、预览、下载）的响应**只能作用于它发出时的那份草稿**，
网络慢、乱序或失败都不会让页面回退到旧状态：

- **预览更新中**：重排、删除、勾选、保存等改动后，工具栏显示「预览更新中…」，此时
  - 「下载纯文本」禁用——预览未追上最新改动前禁止下载，列表 / 预览 / 引用跳转 / 下载始终对应同一份草稿；
  - 「合并所选」与「编辑正文」禁用——避免按旧编号确认合并、按旧显示编号起草引用。
  - 更早发出的预览即使**晚到**也会被丢弃，不会恢复旧列表；正文中的引用按钮按“本次预览自己的顺序”
    跳转，绝不会拿新顺序去解释旧编号。
- **预览失败**：不弹窗打断操作，状态条变为「预览刷新失败（旧响应不会改动草稿）+ 重试」；
  修复网络后点「重试」即可。页面保留上一次成功的预览，下载在重试成功前保持禁用。
- **合并提交期间**：编辑、删除、重排（↑↓ 与拖拽）、勾选、重复点击合并、重新导入全部临时锁定，
  合并按钮显示「合并中…」。
  - **成功**：按合并后的草稿解锁并刷新；
  - **失败**：草稿**不做任何改动**，临时锁定的操作立即恢复，并弹出失败原因。
  - 若等待期间草稿仍发生了变化，迟到的旧合并结果会被整体丢弃，**不会**把已删除的条款“恢复”回来、
    也不会撤回等待期间已接受的任何后续操作。
- **保存提交期间**：编辑器内「保存」显示「保存中…」，「取消」禁用，防止重复提交；
  保存失败时保留编辑器与已输入文本、在原位列出错误；保存成功才退出编辑并刷新。
  - 迟到的旧保存响应不会覆盖之后的编辑，也不会作用于重新导入后的新草稿。
- **重新导入**：确认后当前草稿立即作废、开启全新的草稿世代；此前所有在途请求
  （导入 / 保存 / 合并 / 预览 / 下载）无论成功还是失败，都不会切换草稿、弹错误或改变新草稿的
  提示与按钮状态。导入面板上的「导入」在提交时禁用并显示「导入中…」，成功或失败后恢复。
- **下载提交期间**：按钮显示「下载中…」并禁用；响应回来时若草稿已更新（与请求时不是同一份），
  旧内容不会保存成文件，并提示等预览刷新后重新下载。

## 操作方式

- **调整顺序**：条款卡片左侧 ⠿ 拖拽，或用 ↑ / ↓ 按钮。
- **合并条款**：勾选两条不同条款（每张卡片左上角复选框，一次最多两条），点工具栏
  「合并所选」，确认弹窗中会预览合并后的正文；按当前显示顺序合并，正在编辑正文时不可用。
- **编辑正文**：点「编辑正文」，`Ctrl+Enter`（macOS 为 `⌘+Enter`）快速保存。
- **删除条款**：点「删除」（删除被引用条款前会二次确认）。
- 正文中的 `[[n]]` 是可点击的引用标记，点击后高亮并滚动到目标条款。
- 「重新导入」会清空当前草稿，回到导入页。

## 本地开发（不用 Docker）

需要 Python 3.11：

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

运行测试：

```bash
pip install -r requirements.txt pytest httpx
pytest -q
```

## 接口概览（均为 POST JSON）

| 路径 | 作用 |
| --- | --- |
| `/api/import` | 校验并解析整份导入，错误时 422 + 逐条原因 |
| `/api/save` | 保存一条正文，数字引用按当前显示编号绑定 |
| `/api/merge` | 按当前显示顺序合并两条条款，较后身份并入较前身份，引用统一改指 |
| `/api/preview` | 返回连续编号、解析后文本及全部失效引用 |
| `/api/export` | 无失效引用时返回纯文本，否则 409 拒绝 |
